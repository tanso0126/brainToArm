# brainToArm

뇌파 신호와 손목 카메라, 초음파 센서를 이용해 로봇팔이 물체를 찾고
집도록 만드는 프로젝트입니다.

이 저장소에는 지금까지 사용한 macOS 실험 코드, Arduino 펌웨어,
뇌파 실시간 모니터, 3차원 시뮬레이션, 그리고 친구의 Windows PC에서
실행할 수 있도록 따로 만든 배포판이 함께 들어 있습니다.

## 친구가 가장 먼저 볼 내용

Windows에서 실물 로봇팔을 실행하려면 어려운 명령어를 입력할 필요가
없습니다. 아래 순서대로 파일을 더블클릭하면 됩니다.

1. 이 저장소를 내려받아 압축을 풉니다.
2. `windows_release` 폴더를 엽니다.
3. `START_HERE.txt`를 읽습니다.
4. 처음 한 번만 `SETUP_WINDOWS.bat`을 실행합니다.
5. `OPEN_FIRMWARE.bat`으로 Arduino 펌웨어를 업로드합니다.
6. `CHECK_CAMERA.bat`으로 카메라를 확인합니다.
7. 준비가 끝나면 `RUN_AUTONOMOUS.bat`을 실행합니다.

더 자세한 설명은
[Windows 실물 로봇팔 실행 가이드](windows_release/README_WINDOWS.md)에
있습니다.

> 중요: 자동 실행 전에는 사람의 손, 얼굴, 옷, 케이블을 로봇팔의 이동
> 범위 밖으로 치워야 합니다. 처음 실행할 때는 언제든 전원을 끌 수 있게
> 배터리 스위치나 커넥터 가까이에 한 사람이 대기하세요.

## 자동 실행을 하면 일어나는 일

현재 Windows 실행판의 기본 과정은 다음과 같습니다.

```text
HOME 자세
  → 손목 카메라 자동 선택
  → Arduino Uno 자동 선택
  → 물체 탐색
  → 카메라와 초음파 센서로 접근
  → 집게 즉시 닫기
  → 물체를 든 채 위로 올리기
  → 집게를 닫은 상태로 HOME 복귀
```

자동 실행 중에는 카메라 화면이 계속 표시됩니다. `Ctrl+C`를 누르거나
카메라 창을 닫으면 실행이 중단됩니다.

## 하드웨어 구성

- Arduino Uno 또는 CH340 USB 칩을 사용하는 Uno 호환 보드
- 6축 로봇팔
- 손목에 고정한 USB 웹캠
- HC-SR04 초음파 센서
- 외부 서보 전원과 충전된 배터리
- Uno와 PC를 연결할 USB 케이블

현재 배선은 다음과 같습니다.

| 번호 | 부위 | Uno 핀 | 현재 사용 |
|---:|---|---:|---|
| 1 | 베이스 좌우 회전 | 13 | 실물에서는 고정, 움직이지 않음 |
| 2 | 어깨 | 12 | 사용 |
| 3 | 팔꿈치 | 11 | 사용 |
| 4 | 손목 상하 각도 | 10 | 사용 |
| 5 | 집게 열기/닫기 | 9 | 사용 |
| 6 | 집게 방향 회전 | 8 | 사용 |
| - | 초음파 TRIG | 7 | 사용 |
| - | 초음파 ECHO | 6 | 사용 |

집게 각도는 `90° = 열림`, `180° = 닫힘`입니다. 영상 인식을 위해
왼쪽 집게에는 파란색 테이프, 오른쪽 집게에는 빨간색 테이프가 붙어
있어야 합니다.

### 전원 연결에서 가장 중요한 점

서보 모터는 Uno의 5V 핀으로 구동하지 않습니다. 반드시 별도의 외부
전원을 사용하고, 외부 전원의 GND와 Uno GND를 공통으로 연결해야 합니다.

배터리가 방전되면 다음처럼 보일 수 있습니다.

- 프로그램은 정상 실행되는데 모터가 전혀 움직이지 않음
- 집게만 움직이지 않거나 힘이 부족함
- 물체를 잡으면 다른 관절 명령이 잘 실행되지 않음
- 모터가 바들바들 떨림
- HOME 명령을 보냈는데 중간에서 멈춤

이 증상이 나타나면 코드를 바꾸기 전에 배터리 전압, 충전 상태, 전원
커넥터, 공통 GND부터 확인하세요.

## Windows에서 처음 설치하기

### 1. 저장소 받기

GitHub에서 `Code → Download ZIP`을 누른 뒤 압축을 풉니다. 가능하면
한글이나 특수문자가 없는 짧은 경로에 두는 것이 좋습니다.

예:

```text
C:\brainToArm
```

### 2. 자동 설치

인터넷에 연결한 상태에서 다음 파일을 더블클릭합니다.

```text
windows_release\SETUP_WINDOWS.bat
```

설치기는 Python 3.11을 확인하고, 이 프로젝트만 사용하는 가상환경을
만든 뒤 필요한 패키지를 설치합니다. 다른 Python 프로젝트는 건드리지
않습니다.

설치가 성공하면 초록색 완료 문구가 보입니다. 처음 설치는 PyTorch와
영상 인식 패키지 때문에 수 분 이상 걸릴 수 있습니다.

### 3. Arduino 펌웨어 올리기

`windows_release\OPEN_FIRMWARE.bat`을 더블클릭합니다.

Arduino IDE에서:

1. 보드를 `Arduino Uno`로 선택합니다.
2. `도구 → 포트`에서 Uno의 COM 포트를 선택합니다.
3. 업로드 버튼을 누릅니다.
4. 업로드가 끝나면 `Serial Monitor`와 `Serial Plotter`를 모두 닫습니다.

다른 프로그램이 COM 포트를 사용 중이면 자동 실행 프로그램이 Uno에
연결할 수 없습니다.

### 4. 카메라 확인

`windows_release\CHECK_CAMERA.bat`을 더블클릭합니다.

카메라 영상 하단에 파란색 집게와 빨간색 집게가 모두 보여야 합니다.
`Q` 또는 `Esc`를 누르면 창이 닫힙니다.

### 5. 자동 실행

외부 배터리, Uno USB, 웹캠을 연결하고 물체를 평평한 바닥에 놓은 뒤
`windows_release\RUN_AUTONOMOUS.bat`을 더블클릭합니다.

## 문제가 생겼을 때

### 어떤 문제인지 모르겠음

먼저 `windows_release\DIAGNOSE.bat`을 실행하세요. 이 도구는 연결된
COM 포트와 카메라를 확인하지만 로봇팔은 움직이지 않습니다. 창 전체가
보이게 사진을 찍으면 원격으로 문제를 확인하기 쉽습니다.

### `SETUP_WINDOWS.bat`이 바로 닫힘

- 압축 파일 안에서 직접 실행하지 말고 먼저 압축을 완전히 풉니다.
- 폴더를 OneDrive 동기화 폴더 밖의 `C:\brainToArm` 같은 위치로 옮깁니다.
- 파일을 오른쪽 클릭해 `관리자 권한으로 실행`해 봅니다.
- Windows가 파일을 차단하면 `추가 정보 → 실행`을 선택합니다.
- 그래도 닫히면 `Windows PowerShell`을 열고 다음처럼 실행해 오류를
  확인합니다.

```powershell
cd C:\brainToArm\windows_release
.\SETUP_WINDOWS.bat
```

### Python을 찾을 수 없다고 나옴

설치기가 가능한 경우 `winget`으로 Python 3.11을 자동 설치합니다.
`winget`도 없다면 [Python 3.11 64비트](https://www.python.org/downloads/)
설치 파일을 받아 설치하세요. 설치 화면에서 반드시
`Add Python to PATH`를 선택하고, 설치 후 열려 있던 창을 닫은 다음
`SETUP_WINDOWS.bat`을 다시 실행합니다.

### 패키지 설치 실패 또는 인터넷 오류

- 인터넷 연결과 학교·회사 방화벽을 확인합니다.
- VPN이나 프록시를 잠시 끄고 다시 시도합니다.
- 디스크에 최소 수 GB의 여유 공간을 확보합니다.
- 설치를 다시 실행해도 됩니다. 이미 설치된 항목은 재사용됩니다.

### 카메라를 열 수 없음

1. `설정 → 개인정보 및 보안 → 카메라`로 이동합니다.
2. `카메라 액세스`와 `데스크톱 앱에서 카메라에 액세스`를 켭니다.
3. Zoom, Teams, OBS, 브라우저 등 카메라를 사용하는 앱을 모두 닫습니다.
4. 웹캠 USB를 뺐다가 다른 USB 포트에 다시 연결합니다.
5. `CHECK_CAMERA.bat`을 다시 실행합니다.

카메라가 여러 개라 잘못 선택되면 명령 프롬프트에서 번호를 지정합니다.

```bat
windows_release\CHECK_CAMERA.bat --camera 1
```

번호는 `0`, `1`, `2` 순서로 바꿔 확인하면 됩니다.

### 파란색 또는 빨간색 집게를 못 찾음

- 두 색 테이프가 카메라 영상 하단에 실제로 보이는지 확인합니다.
- 테이프가 작거나 접혔거나 손상되었으면 다시 붙입니다.
- 강한 역광과 과노출을 줄입니다.
- 렌즈 보호 필름과 먼지를 확인합니다.
- 카메라가 수리 전과 같은 위치와 방향으로 단단히 고정되었는지 봅니다.

### Arduino Uno를 찾을 수 없음

- 장치 관리자의 `포트(COM 및 LPT)`에서 Uno 또는 `USB-SERIAL CH340`을
  확인합니다.
- 충전 전용 USB 케이블이 아닌 데이터 통신 USB 케이블을 사용합니다.
- Arduino IDE의 Serial Monitor와 Serial Plotter를 닫습니다.
- 다른 시리얼 프로그램도 모두 닫습니다.
- Uno 호환 보드라면 CH340 드라이버가 필요할 수 있습니다.
- `DIAGNOSE.bat`에 표시된 COM 번호를 직접 지정할 수 있습니다.

```bat
windows_release\RUN_AUTONOMOUS.bat --camera 1 --port COM5
```

### `펌웨어 HOME 자세가 일치하지 않습니다`와 비슷한 오류

Uno에 이전 펌웨어가 들어 있는 상태입니다. `OPEN_FIRMWARE.bat`을 열어
현재 저장소의 펌웨어를 다시 업로드합니다.

### 모터가 반대로 움직이거나 기구가 걸림

수리하면서 모터 커넥터 순서, 서보 혼 위치, 링크 조립 위치가 바뀌면
기존 보정값과 실제 움직임이 달라질 수 있습니다. 자동 실행을 반복하지
말고 즉시 전원을 끈 뒤 다음을 확인하세요.

- 2·3·4번 모터가 원래 방향으로 움직이는지
- 집게가 `90°`에서 열리고 `180°` 방향으로 닫히는지
- HOME에서 집게나 링크가 로봇 몸체에 걸리지 않는지
- 카메라와 초음파 센서가 흔들리지 않는지

기구 위치가 달라졌다면 소프트웨어 보정값도 다시 측정해야 합니다.

### 자동 실행이 중간에 멈춤

창에서 가장 마지막에 나온 한국어 오류를 확인하세요. 자동 실행은
다음과 같은 경우 움직임을 중단할 수 있습니다.

- 카메라 영상이 끊김
- Uno 연결이 끊김
- 관절 명령이 허용 범위를 벗어남
- 제한 시간 안에 물체를 찾지 못함
- 프로그램이 예상한 HOME 복귀 상태에 도달하지 못함

배터리 문제인지 프로그램 문제인지 구분하려면 먼저 `DIAGNOSE.bat`을
실행하고, 카메라와 COM 연결이 정상이라면 배터리를 완전히 충전한 뒤
다시 시도하세요.

## 뇌파 기능

polyG-I 뇌파 장치의 통신 분석과 사용 방법은
[뇌파 장치 통신 문서](docs/EEG_DEVICE_COMMS.md)에 정리되어 있습니다.

현재 설계의 핵심은 다음과 같습니다.

- 오류 관련 전위(ErrP): 8번 채널을 사용해 로봇 행동에 대한
  `맞음/아님` 반응을 감지
- 인지 부하: 1·2·3·4번 채널의 세타 파워와 8번 채널의 알파 파워로
  세타/알파 비율(TAR)을 계산
- TAR가 높으면 로봇의 자율 판단 비중을 높임
- TAR가 낮으면 사람의 ErrP 반응 비중을 높임

뇌파 수치는 의료 진단용이 아니며, 전극 접촉 상태와 공통 잡음,
움직임 잡음의 영향을 크게 받습니다.

## 검증 상태를 정확히 읽는 법

저장소에는 성공과 실패를 모두 남긴 날짜별 검증 기록이 있습니다.

- [실물 파지 검증 기록](docs/PHYSICAL_GRASP_VALIDATION.md)
- [HOME부터 시작한 자동 파지 검증 기록](docs/AUTONOMOUS_GRASP_VALIDATION.md)

이 문서들은 해당 날짜 당시의 기록입니다. 이후 코드가 더 바뀌었더라도
과거 실패를 성공으로 고쳐 쓰지 않았습니다.

현재 Windows 배포판은 패키지 설치, 모듈 불러오기, AI 모델 무결성,
카메라 선택 로직, COM 선택 로직을 자동 테스트했습니다. 그러나 친구의
Windows PC와 수리 후 실물 로봇팔 조합은 현장에서 최종 확인해야 합니다.

## 백업과 배포 기준

- macOS 실물 실험 기준 태그: `physical-macos-baseline-2026-07-30`
- 최초 Windows 인수인계 태그: `windows-handoff-v1`
- Windows용 코드는 기존 실물 코드를 덮어쓰지 않고
  `windows_release/`에 별도로 추가했습니다.

수정하기 전에는 새 Git 커밋을 만들고, 잘 되던 버전의 태그를 지우거나
이동하지 마세요. 문제가 생기면 위 태그로 당시 상태를 확인할 수 있습니다.
